# Unified Device Credential — Design

**Status:** proposed
**Date:** 2026-11-09
**Supersedes:** PR #26 (`feat/desktop-bearer-auth`) — the standalone `DesktopToken` entity
**Related:** PR #23 (deep-link routing), PR #24 (static export), PR #25 (API base)

## Intent

One machine is represented by three unrelated credentials today:

| Credential | Principal | Accepted by | Lifetime |
|---|---|---|---|
| `AgentDevice` token | a device running the agent | `/ws/agent` only | no expiry |
| `DesktopToken` (PR #26) | a desktop UI session | the REST API | 30 days |
| Sidecar secret | a local process | `127.0.0.1:<port>` | per app run |

The desktop runs the agent binary as a sidecar (`tauri.conf.json > bundle.externalBin`), and `SidecarCommand` can already open the agent WebSocket when it receives `--server-url` and `--token` (`backend/src/ApiDot.Agent/Commands/SidecarCommand.cs:271-290`). The machine is therefore one device that can be a dispatch target, but the app never gives it an identity.

This design makes the device the single concept: one credential per machine, used by the desktop UI over REST and by its sidecar over WebSocket, with one revocation point.

## Goals

- One device record per machine, reused across logins.
- One token authenticates both the REST API (UI) and `/ws/agent` (sidecar).
- Revoking the device in the UI ends the UI session and the WebSocket together.
- The sidecar connects to the server after login and becomes a dispatch target addressable from the web or another client.
- Local direct execution (`127.0.0.1/execute`) keeps working, including offline.
- The web cookie session is unchanged.

## Non-goals

- OS keychain storage. The session token lives in the user profile (`~/.apidot/session.json`, 0600) for now.
- Merging the sidecar's ephemeral local secret into the device token.
- Multiple accounts per OS profile beyond "one app profile, one signed-in user".
- Renaming `AgentDevice`/`AgentDevices`. The name is kept to avoid a table rename; the entity is documented as "a device that may run the agent, the desktop UI, or both".

## Anti-goals

- A device token accepted as the local `/execute` capability. That would turn a server credential into a local authority and make offline execution depend on the server.
- Silently recreating a device that an operator revoked.

## Constraints

- SQLite with EF Core migrations applied at startup (`ApplyDatabaseMigrations`).
- No new NuGet/npm/cargo packages.
- The web build (`output: 'standalone'`) and all existing tests must keep working.
- Tokens are stored hashed only (SHA-256 of a 32-byte random value).
- `APIDOT_AUTH_ENABLED` bypass and the `DevRoot` scheme keep working.
- Existing agent devices (issued before this change) must keep connecting.

## Approaches considered

- **A. Device credential with scopes (chosen).** Extend `AgentDevice` with `Scopes`, `ExpiresAtUtc`, `LastUsedAtUtc` and `DeviceKey`; one token per machine; REST requires `rest`, WebSocket requires `ws`. Local `/execute` keeps its ephemeral secret.
- **B. Device + derived short session.** The device token is `ws`-only and long-lived; the UI exchanges it for a short session token. Safer on disk, but adds a second client credential and an endpoint — rejected as the opposite of the simplification requested.
- **C. Keep three credentials.** No unification; the desktop cannot be a dispatch target without registering a separate device. Rejected.
- **D. Merge the sidecar secret too.** The sidecar would validate the device token locally, which it cannot do offline, or accept it unverified. Rejected.

## Design

### Data model

`AgentDevice` (table `AgentDevices`) gains:

| Column | Type | Notes |
|---|---|---|
| `DeviceKey` | string(64), nullable | Random id generated by the app; identifies the machine for reuse. Legacy rows are null. |
| `Scopes` | int | `[Flags] DeviceScope { Ws = 1, Rest = 2 }`. Legacy rows are backfilled to `Ws`. |
| `ExpiresAtUtc` | DateTime?, nullable | `null` means no expiry. `rest` tokens use 30 days; `ws`-only tokens use `null`. |
| `LastUsedAtUtc` | DateTime?, nullable | Updated at most once per hour on REST authentication. |

Lookup: the latest non-revoked row for `(UserId, DeviceKey)`. No unique index on `DeviceKey`, because a revoked row must not block a new registration with the same key.

`DesktopToken` and its migration (PR #26) are removed. The table never reaches `dev`.

### Issuance

`POST /api/auth/desktop-exchange` (one-time SSO token → user) gains optional body fields: `deviceKey`, `deviceName`, `deviceOs`, `agentVersion`.

- If a non-revoked device matches `(userId, deviceKey)` and the key is not null: rotate its token (new hash and prefix), update name/os/version, extend `ExpiresAtUtc` to 30 days, keep the row id.
- Otherwise create a device with `Scopes = Rest | Ws`, `ExpiresAtUtc = now + 30d`, and a generated `DeviceKey` when the request did not carry one.
- The JSON response body is unchanged. New/changed response headers: `X-Desktop-Access-Token`, `X-Desktop-Access-Token-Expires`, `X-Desktop-Device-Id`, `X-Desktop-Device-Key`.
- The cookie sign-in stays for backward compatibility.

`POST /api/agent/devices` (cookie-authenticated) keeps creating headless devices, now explicitly `Scopes = Ws` and `ExpiresAtUtc = null`. The raw token is returned once, as today.

### Authentication

- `DeviceTokenAuthenticationHandler` (renamed from `DesktopBearerAuthenticationHandler`, scheme `DeviceToken`): hash lookup, reject revoked, require `Scopes.HasFlag(Rest)` and not expired, refresh `LastUsedAtUtc` at most hourly, emit the same claims as `SignInAsync`.
- The `ApiDotDefault` policy scheme selector keeps its shape: an `Authorization: Bearer` header routes to the device scheme; otherwise bypass/cookie.
- `/ws/agent` (`AgentWebSocketHandler`): after the existing hash lookup and revocation check, require `Scopes.HasFlag(Ws)` and not expired. A `rest`-only token cannot open the channel.
- `AgentDeviceAuthorization`, `ICurrentUserContext` and workspace authorization are unchanged.

### Sidecar lifecycle

The sidecar stays a local HTTP process bound to `127.0.0.1`; the ephemeral secret keeps protecting `/execute`, `/auth/*` and the new endpoints.

- `POST /connect` (secret-protected), body `{ serverUrl, token }`: stops any current connection and starts `AgentClient.StartAsync`. Idempotent.
- `POST /disconnect` (secret-protected): cancels the connection; `/execute` keeps working.
- `GET /agent-status` (secret-protected): `{ connected, deviceName, serverUrl }` for diagnostics.
- The Tauri app calls `/connect` after login and `/disconnect` on logout/401. The sidecar never persists the token.
- The CLI auto-connect path (`--server-url` + `--token` or `APIDOT_AGENT_TOKEN`) stays for headless use.

### Client session storage

- `~/.apidot/session.json`, mode 0600, written by the Tauri app (not the agent): `{ userId, deviceId, deviceKey, accessToken, expiresAt }`.
- New Rust commands: `load_session`, `save_session`, `clear_session`; the file is created with `0600` and the directory with `0700`, matching `storage.rs`.
- At boot the app hydrates the in-memory token (`setAccessToken`) from the session file.
- On any `401`, the app clears the session, calls `/disconnect`, and navigates to `/login`.
- On logout: `DELETE /api/auth/device-token` (renamed from `/desktop-token`) revokes the presented token, then `/disconnect`, then `clear_session` and `setAccessToken(null)`.

### UI

- Device list: scope badges (`Desktop`, `Agent`) and a marker for the current device.
- Revoking the current device logs the UI out on the next request (401 path) and drops the WebSocket.
- No new settings beyond the server URL added in PR #25.

### Migration and compatibility

- One migration adds the four columns and backfills `Scopes = 1` for existing rows.
- Existing agent tokens keep connecting: `Ws` scope, no expiry.
- #26 is reworked: the `DesktopToken` entity, configuration, migration and handler are removed from the branch before merging; the rest of #26 (exchange headers, CORS, revocation endpoint) is adapted to the device entity.
- The web cookie flow is untouched.

### Testing

- Unit: scope and expiry enforcement; reuse by `(userId, deviceKey)`; token rotation invalidates the previous value; revoke ends both channels; legacy row (no scopes) can open WebSocket but not REST; `LastUsedAtUtc` throttle.
- Integration: exchange creates a device and returns the headers; REST with the token; WebSocket with the token; wrong scope 401; expired 401; revoked 401; CORS preflight unchanged.
- Sidecar: `/connect` requires the secret; starts and stops; idempotent; `/execute` works while disconnected.
- Client: session read/write/clear; boot hydration; 401 clears the session and disconnects; logout revokes.
- No test may require a real browser or a signed desktop bundle.

### Rollout

1. Backend schema + auth (device scopes, exchange, WS check).
2. Sidecar endpoints + Tauri commands + client session storage.
3. UI badges and 401 handling.
4. Rebuild #26 on top; integration check; then R3 (installed-app validation).

## Resolutions from the builder check

1. **Logout is not revocation.** Logout clears `TokenHash`, `TokenPrefix` and `ExpiresAtUtc` and leaves `IsRevoked = false`, so the row survives and `Collection.TargetDeviceId` references stay valid. Operator revocation sets `IsRevoked = true` and blocks reuse of `(UserId, DeviceKey)`.
2. **`DeviceKey` survives the session.** `session.json` keeps `deviceKey` when the token is cleared; it is a machine id, not a secret. When the exchange answers `403 device_revoked`, the app clears the key and asks the user to sign in again, which registers a new device explicitly.
3. **Branch strategy.** The unified work starts after #23, #24 and #25 merge; #26 is closed, not merged, so `DesktopToken` never reaches `dev` and no deletion is planned.
4. **Local login also issues the credential.** `/api/auth/local` and `/api/auth/desktop-exchange` share one issuance path and return the same `X-Desktop-*` headers, so a self-hosted deployment without OIDC keeps a working desktop.
5. **Boot reconnect.** `session.json` also stores `serverUrl`. At boot, with a session present, the app calls `GET /api/auth/me`: 401 clears the session; 200 calls the sidecar `/connect`. A stale token is caught over HTTP instead of only as a WS close.
6. **Bypass mode does not dispatch.** With `APIDOT_AUTH_ENABLED=false` there is no exchange and no device token, so the app skips `/connect`; `/ws/agent` keeps requiring a real device. R3 runs with auth enabled.
7. **CORS.** The desktop exchange stops sending `credentials: 'include'` (the one-time token is in the body) and the policy exposes `X-Desktop-*` through `WithExposedResponseHeaders`; no `AllowCredentials`. The cookie flow stays for the web.
8. **Terminal auth failure in the agent.** `AgentClient` stops retrying after a `PolicyViolation` close, reports `unauthorized`, and the app treats it like a 401 (disconnect and sign in).

## Decisions left to the builder

- Exact naming of the new scheme (`DeviceToken` vs keeping `DesktopBearer`) — cosmetic, if claims and selector stay as described.
- Whether the device list shows a `last used` timestamp.
- Whether `POST /connect` returns the bound port or the app keeps using `get_sidecar_info`.
